## 真实运行环境

所有依赖安装、Python 工程检查、原生程序运行、截图与行为测试均在腾讯云 `tencent-opencloudos` 完成。控制端只编辑隔离源文件、传输文件和查看截图。

- OpenCloudOS / Linux `6.6.119-49.23.oc9.x86_64`，glibc 2.38。
- Python 3.11.6；PySide6-Essentials 6.12.0；Shiboken 6.12.0；Pillow 13.0.0；锁定见 `requirements.txt`。
- Qt Widgets / Fusion / Noto Sans CJK SC，QPA 为 `xcb`，非 HTML、非 offscreen。
- 私有 Xvfb 1600×1100×24，`-displayfd` 分配空闲显示，运行记录分配了 `:0`；测试后退出自己的 Xvfb 进程。
- 第一轮启动缺 `libxcb-cursor.so.0`。仅下载并解包 `xcb-util-cursor-0.1.4-3.oc9.x86_64.rpm` 到 `native-deps/root`，由进程的 `LD_LIBRARY_PATH` 使用。没有全局安装或修改包源、服务、凭证。
- Xvfb 没有窗口管理器，所有截图是真实已暴露的 X11 顶层窗口内容；没有伪造系统窗口装饰。

## 未验证与限制

- 没有验证 Windows/macOS、Wayland、真实显示器、系统级安装或打包安装器。
- 没有窗口管理器，所以模态对话框关闭后的 OS 焦点恢复未验证；测试脚本在相关边界通过 xdotool 显式恢复主窗口 X11 焦点。不能据此声称桌面系统自动焦点恢复已通过。
- 没有用屏幕阅读器做完整无障碍审计；只验证了列出的键盘路径、可见焦点与文本状态。
- 样例是代码绘制的测试图片，未验证 RAW、大批量超大照片、外部磁盘、磁盘满、断电中断或复杂色彩配置；程序目前输出JPEG/PNG并处理EXIF方向，没有摄影色彩管理或RAW流程。
- 未测试并发第三方程序写入同一输出目录；导出代码用同目录临时文件、验证后硬链接发布来避免覆写已有路径，此实现仅在本轮Linux文件系统上实际验证。
- 未做恢复队列/断点续传功能；关闭时请求停止并等待当前文件处理结束。
- 初始两次行为脚本失败均保留原日志；xcb 首启失败输出从实际工具结果转存为 `evidence/initial-xcb-startup-failure.txt`；前两次行为失败来自无窗口管理器导致的测试活动焦点缺失，随后增加显式 X11焦点前置条件。没有删除这些记录来冒充一次通过。
