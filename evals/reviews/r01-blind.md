# 独立成品评审

已实际查看 web-desktop.png、web-mobile.png、game-paused.png、game-resized.png，并只读核对对应源代码。另以临时回环 HTTP 服务器和独立 Chrome 进程测试网页成品；已关闭临时进程。未读取技能文件、旧验证报告或修正结论。游戏只依据截图和源代码，未复测实体手柄。

总体判断：A 的纸色、宋体、细分隔线、目录栏和街巷照片构成了完整的期刊语言，桌面标题与正文层级清楚；照片中的树影、石板路、旧墙与正文互相支撑。手机布局没有截图可见的横向溢出，收藏状态也有明确文字。B 的深蓝与金色轨道形成鲜明主题，暂停状态、继续航行和次要操作的优先级清楚；两种尺寸均未见主菜单遮挡。视觉完成度成立，但不能据此抵消下面的交互与信息问题。

可证实的问题：

- **A／中：手机翻篇不回到新文章开头。** 位置：底部“上一篇／下一篇”。390×844 的隔离浏览器测试中，从文章底部点击“下一篇”后，标题已变为“巷子尽头的早餐”，但滚动位置仍是 624px，新标题顶部为 −382px。用户会停在新文章的后半段，需手动上滑才能确认标题并从头读。证据：浏览器复现；web/src/main.js:54–55 仅更换内容，没有滚动或焦点处理。
- **A／中：目录切换会丢失当前焦点。** 位置：桌面目录与手机展开目录的文章按钮。隔离浏览器中，先聚焦目录项再激活，document.activeElement 变成 BODY；源代码在点击后清空并重建整个目录。键盘使用者失去可见的操作位置，也没有移到新文章标题；标题虽已设 tabindex="-1"，但未被使用。证据：浏览器复现；web/src/main.js:16、27、45；web/index.html:18。此测试用程序激活已聚焦按钮，没有模拟实际按下 Enter；焦点丢失来自共用点击处理路径。
- **A／低：阅读时长与实际内容明显不符。** 位置：作者右侧“8分钟／6分钟／5分钟”。三篇实际正文分别仅 115、109、97 字符（含标点），且正文之后直接是收藏和翻篇，没有剩余章节。该元信息不能帮助读者估计投入时间，会降低期刊的可信度。证据：实际 DOM 统计、web/src/main.js:4–6。演示内容的明确标注降低了真实性误解，但没有解释时长差异。
- **B／中，依显示环境而定：缩窗时键位说明过小。** 位置：game-resized.png 左下角。1024×640 截图中 Enter、Esc、A、B 及“确认／返回”明显细小；源代码将 1440×900 整体缩放，13px 键名字和 14px 说明随之变为约 9.2px、10px。主菜单仍清楚，但初次使用者更难辨认操作方式。证据：实际截图；game/game.py:108–111、115–119。可将操作提示设置为不随画布继续缩小的最小字号；这不是主菜单交互失效的证据。

不应据此强改的取舍：手机大图先于正文符合图文期刊定位；首尾篇循环在界面中给出了目的标题，原请求没有禁止循环；演示内容与合成图片均已明示，不能因为缺真实城市名就判定造假；游戏设置只有“星轨显示”不能单凭选项少判为不合格；没有存档丢失证据，也不能要求“返回标题”必须二次确认。

未知：实体手柄的识别、不同型号按钮映射、热插拔，以及真实游戏存档与暂停期间的完整模拟状态。源码显示角度更新只发生在 playing 状态，足以支持这份演示中的场景暂停语义，不能扩展为完整游戏的运行保证。截图与合成输入通过也不足以确认这些未知项。
