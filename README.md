# ui-skill

先生成并查看参考图，再据图实现 UI。构图跟着内容走，交互按平台习惯做，文案说具体的事。适用于网页、移动 App、小程序、桌面软件、游戏界面、组件和视觉原型。

用户可以明确要求跳过生成图。交互和实现沿用目标平台的约定。

## 使用

将整个仓库作为 `ui-skill` 技能目录放入 Codex 的技能目录，保留 `SKILL.md`、`agents/`、`references/` 和 `assets/` 的相对路径。正常自动发现保持开启，也可以显式调用：

```text
使用 $ui-skill，为我的阅读应用设计并实现首页，支持桌面和手机。
```

```text
使用 $ui-skill，只优化现有登录框，保留品牌色、技术栈和页面其他部分。
```

```text
使用 $ui-skill，为现有游戏做暂停菜单，沿用美术风格，支持键盘和控制器。
```

图像生成需要当前环境实际提供相应工具。技能本身不包含模型、API 密钥或付费服务；不可用时会说明阻碍。界面实现和验收使用所在项目与环境已有的工具。

## 工作方式

- 新建或修改视觉时，先生成并查看可用的界面参考；局部改动限定范围。
- 用户原始要求、品牌、内容和技术栈优先于生成图；精确复刻保留原始参考约束。
- 根据内容、品牌、主要任务和输入方式决定构图、排版与素材；复查无依据的卡片网格、套话、虚构背书和装饰堆叠，不强制所有作品使用同一种风格。
- 布局默认简洁。主要内容和操作直接可见；次要但有用的信息按需展开，无用信息直接删除。
- 文案写清动作和状态；说明与回复删掉重复铺垫、空泛判断和机械句式，保留事实与必要细节。
- 同一任务沿用已选参考，不因每次调整样式重复生成；只有用户要求先确认时才等待确认。
- 将参考拆成真实组件与交互，补齐必要状态和适配规则，在目标平台实际查看截图、操作主要路径。
- 只要图片时直接交付图片。纯功能修复、技能文档维护、只读评审和精确数据绘图不触发本流程。

## 维护验证

修改后使用 `skill-creator` 自带的 `scripts/quick_validate.py` 检查技能目录，并检查 YAML、相对链接和资源是否有效。该检查不能证明实际生成质量；按行为用例在可用环境执行，并记录调用、截图和操作结果。没有运行的场景标记为未运行，不能计为通过。

本仓库是技能包，没有应用构建命令。需要端到端验证时，在隔离目录让技能完成一个真实 UI 任务，在用户指定环境构建、运行、截图并检验主要操作；测试界面无需成为技能运行时依赖。

首轮的检查、样例截图和未覆盖范围见 [腾讯云验证记录](evals/validation.md)，后续发现的问题见 [独立成品评审](evals/reviews/r01-blind.md)。

后续按 [持续迭代流程](evals/iteration.md) 固定技能版本、生成新案例、独立评审并回测。每轮记录实际问题和技能改动，不用一次运行通过或主观分数宣布设计能力已经验证完毕。
