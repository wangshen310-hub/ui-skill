# 设计方向与去模板

用于新建与重新设计 UI。目标是让作品有与用途相符的视觉判断，覆盖网页、移动端、桌面、游戏及组件，不把某一种流行风格规定为“高级”。用户已有明确方向时，深化其要求；局部修改尊重已有设计。

## 先形成设计判断，再描述风格

从实际内容中找布局依据，简要回答：

- 用户在这个界面最先要看什么、最常做什么？关键内容是文本、图片、数据、时间关系还是空间关系？
- 受众、品牌气质与使用情境要求怎样的信息密度、阅读节奏和反馈强度？
- 在目标平台上，用户用什么输入方式操作？哪些导航与控件惯例需要保留？
- 哪个视觉特点最能体现该任务：字体与节奏、素材裁切、网格比例、色彩关系、图形语言或工作区结构？

据此定下构图、排版、配色角色、素材与细节的共同方向。不要求每个项目都选相同数量的风格词、方案或设计变量。方向可判断时直接推进；需要探索时用少量有实质差别的候选，不靠逐个换色制造差异，不默认停下来索要确认。

用一句具体的设计判断连接任务与画面，例如“要比较同一组属性，优先让同列对齐”，或“用户持续编辑正文，让工作区占主要空间，低频设置收在旁边”。这句话应能解释区域比例与组织方式；“简约、高级、有质感”解释不了布局。

先带入代表性的标题、正文、图片比例、条目和数值，再定结构。重复内容按需要比较的关系组织：同类项目可成行，时间关系可成轴，连续文字需要阅读节奏。内容不同的区域不必硬凑等宽、等高和同一种容器；重复操作也不必为追求变化拆成不同样式。

没有品牌要求时，根据内容气质、素材与使用环境选定具体方向，并说得出选择的依据。不要照搬本指南示例、上一案例或图像模型惯用的配色与字体；同一产品已有的语言则继续使用。

## 先删掉没有用的信息

默认让布局简洁。逐块问：删掉它，用户会不会少一个必要判断、找不到操作，或误解当前内容？没有影响就删掉。不能仅因为模板里常见，就放上欢迎语、统计、介绍、标签、推荐区或说明卡片。

主要内容与操作直接可见；有用但低频的信息可以放进详情、展开区或相关步骤。不要为收纳本来就无用的信息增加一层菜单，也不要为了画面空一点隐藏必要状态、清楚的标签和重要提醒。

简洁也适用于高密度界面。数据工作区可保留必要的行列与工具，用对齐、分组和字重减少干扰。阅读、游戏等界面可以用图片或场景营造气氛，只要它确实属于内容或体验。留白、装饰数量和屏幕信息量没有统一配额。

工具名称、实现说明、测试进度和设计过程留在交付说明里；只有会影响产品用户判断时才出现在界面中。

## 同一方法，导出不同界面

下表说明如何从内容推导决定，不是固定模板，也不规定视觉风格：

| 任务特征 | 设计要解决的重点 | 可以形成辨识度的地方 |
| --- | --- | --- |
| 长文阅读、资料浏览 | 可读行长、层级、注释与阅读进度 | 文字节奏、页边关系、目录与内容的比例 |
| 图片、商品、作品展示 | 素材质量、比较与选择 | 原始素材的裁切和尺度、陈列密度、细节信息的位置 |
| 高频操作、数据工作区 | 扫读、检索、选择、批量操作和反馈 | 行列结构、工具区关系、密度与清楚的状态语义 |
| 移动任务流程 | 单手触达、渐进信息、连续反馈 | 主操作位置、内容分组、原生导航与过渡 |
| 桌面创作工具 | 工作区、面板、快捷操作与窗口变化 | 面板比例、画布优先级、选中及编辑状态 |
| 游戏界面 | 操作输入、状态可见、沉浸感与遮挡控制 | 世界观一致的字体/图形、HUD 位置、状态反馈节奏 |
| 独立组件 | 所在设计系统、语义和全部相关状态 | 对齐、字重、边框、图标与反馈的一致细节 |

例如数据工作区可能需要重复行、表格或卡片，这取决于比较任务；不能为了“反模板”牺牲扫读。极简工具也可以很有辨识度，不必添加大图、非对称布局或动效证明设计感。

## 让视觉选择彼此配合

- **构图：** 先明确主次、分区和比例；留白有阅读或操作目的。需要非对称时保证关系清楚，信息密集时让密度有秩序。
- **排版：** 字体气质与内容相符，用实际标题、长句和数值调整字号、字重、行长与行距。相邻标签和控件检查基线；需要纵向比较的数字检查对齐与位数。确认实际可用字体及回退，中文、英文和混排都要查看，不能只凭字体名推断效果。
- **颜色：** 分清背景、表面、文字、强调和状态角色。让主要操作醒目；图中低对比文本在实现时修正，语义颜色不随意挪用。
- **形状与细节：** 用稳定的对齐线与间距表达分组，组内关系比组间更紧密；圆角、边框、阴影、图标笔画和组件密度保持体系。图标与文字的视觉中心需要实际查看，不能只看外框居中。减少没有作用的分隔与容器，确需分组时保留。
- **素材：** 使用与内容有直接关系的图片和插画，明确裁切、主体及占比。缺少真实商品或人物素材时注明占位，不编造产品效果或背书。图标承担辨识与操作，不靠重复 emoji 充当整套视觉语言。
- **动效：** 用于状态变化、空间关系或反馈。按平台和用户要求实现；避免无目的循环、阻塞主流程或让每个区域都以相同方式出现。

将这些决定写进生成提示词；“精美、高级、现代、不要 AI 味”只能表达期待，不能替代内容与构图描述。生成结果中若仍然出现不相关区块，先修正提示与参考，再实现。

## 单独检查视觉完成度

参考图与实现画面都要回答这些问题，按实际问题修改：

- 视线先落在需要阅读、比较或操作的内容上吗？装饰、标题和主按钮是否在争抢同一层注意力？
- 去掉无作用的说明与容器后，信息是否更容易理解？有用的留白是否被无关区块填满？
- 相邻区域的尺度、对齐、字形和间距是否协调？长标题、混排和真实素材是否破坏了这种关系？
- 选中、焦点、禁用、错误等状态是否延续同一视觉语言，并能清楚区分？
- 换掉产品名后，内容组织、素材和操作仍能说明这是哪类产品吗？若辨识度只剩一套颜色，回到结构与内容调整。

先修主次与区域比例，再修排版、素材和细节。一次无溢出检查或一次运行成功不能回答这些问题，也不需要把答案换算成审美分数。

## 去模板复查

在查看生成图、实现后对照截图时各复查一次，选择真正存在的问题修正：

| 可见征兆 | 应追问的原因 | 修正方向 |
| --- | --- | --- |
| 换掉产品名就像任何另一个产品 | 内容是否实际影响了结构？ | 用该产品的任务、素材比例和信息关系重排重点 |
| 每个区块都是同样的卡片 | 容器是在分组还是只是填满页面？ | 合并无意义容器；按比较、阅读或操作需要组织 |
| 许多标签、说明和次要指标围着主内容 | 这些信息是否影响当前判断或操作？ | 删除无用信息；有用的次要内容按需展开 |
| 空泛的巨大标题、胶囊标签和重复 CTA | 是否误套了营销结构？ | 使用具体标题和实际任务入口，保留适用的营销内容 |
| 渐变、光晕、纹理、阴影同时抢注意力 | 是否缺少主次而依赖效果填充？ | 保留服务视觉重点的效果，减弱竞争的元素 |
| 虚构统计、评价、头像和奖项 | 是否用假信息营造“成品感”？ | 删除无依据内容，使用真实来源或清楚的演示数据 |
| “开启无限可能”“全面赋能”等套话 | 文案是否解释了用途、状态和动作？ | 写明用户能做什么、需要什么、接下来会发生什么 |
| 原生 App 像缩小的营销网页 | 是否忽略平台和输入方式？ | 恢复平台导航、信息密度、触达和反馈习惯 |
| 风格独特但很难操作 | 视觉选择是否损害了任务？ | 保留辨识度，修复标签、可读性、焦点与操作路径 |

不要把上表变成禁用清单。卡片、渐变、居中标题、胶囊按钮、对称网格等都可能适合某个任务；需要移除的是无依据的重复和装饰堆砌。修改后重看全局，确保作品仍是统一的设计，而非拼接多个互相冲突的风格。
