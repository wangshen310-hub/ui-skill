# 视觉与交互验收

用于已经实现的 UI。依据任务选择检查，不把每个小改动都变成整站审计。图片交付只需检查构图、内容、图像质量和输出文件，不适用下面的界面操作检查。

## 先确认验收对象

记录实际运行的版本、页面或路由、运行环境、视口和测试状态。用户指定远程服务器时，在指定服务器上构建、运行和截图；本地查看下载的截图可以辅助比较，但本地构建不能冒充远程测试。

使用仓库已有的构建、类型检查或测试命令，只运行与改动有关的检查。没有构建步骤的静态页面或技能包，说明采用了什么检查，不虚构一条应用构建命令。

目标平台的运行或预览工具不可用时，记录阻碍与未验收项；不要用源码检查或 HTTP 成功状态代替视觉验收。设计图、浏览器原型和真正运行的原生应用是不同的交付层，不相互冒充。

## 按平台选择证据

| 目标 | 运行与视觉证据 | 重点操作 |
| --- | --- | --- |
| 网页 | 实际浏览器、目标路由及视口截图 | 导航、键盘、表单、窄屏和滚动 |
| 移动 App | 对应构建、模拟器或真机截图 | 触控、返回、软键盘、安全区域与相关系统状态 |
| 小程序 | 对应开发工具或真机预览 | 页面栈、平台组件、授权入口及主流程 |
| 桌面软件 | 实际程序窗口及尺寸/缩放记录 | 焦点、键鼠、菜单、快捷操作与窗口变化 |
| 游戏界面 | 目标引擎中的实际运行画面 | HUD 遮挡、暂停、输入模式、控制器焦点与状态反馈 |
| 组件 | 所属平台中的实际宿主；隔离预览用于辅助检查 | 宿主分配的空间、相关状态、输入方式，以及适用的重复实例与移除后恢复 |
| 设计图或视觉原型 | 实际查看导出图或原型预览 | 构图、内容、平台惯例及用户要求的交互层级 |

只选择目标对应的行。不能为验证方便将原生应用改成网页；缺少工具时先说明未验证范围，按已有授权处理替代方式。

## 视觉：在可比较的条件下查看

1. 在与参考接近的屏幕或窗口打开正确界面，等待字体、图片和主要内容就绪。固定会影响对照的主题、语言、滚动位置和交互状态。
2. 截图并实际查看；内容较长时检查首屏与涉及的下方区域。生成图片尺寸不等于 CSS 视口、设备逻辑分辨率或窗口尺寸，比较时先对齐可见内容区域和比例。
3. 先比较主要区域的位置、比例、留白和视觉重点，再比较排版、配色、素材及细节。对明显偏差按影响从大到小修正。
4. 对修改后的同一页面重新截图和查看；必要时复测受到影响的相邻组件。记录仍存在的显著差异与原因。

再按[视觉完成度](art-direction.md#单独检查视觉完成度)核对设计本身：主次和比例是否合适，真实文字与素材是否协调，去掉无作用的信息后是否仍然完整。参考图也可能平庸，不能只因实现与它接近就停止判断。

查看时也检查信息量：无关指标、重复提示、装饰性标签和过程说明有没有抢占主内容？删掉没有用的区块后重新看布局，确保主要操作和必要状态仍然清楚。

以下证据各有局限：

| 证据 | 可以证明 | 不能独自证明 |
| --- | --- | --- |
| 构建、类型或单元测试 | 覆盖范围内的工程正确性 | 页面好看、还原准确、真实服务可用 |
| 浏览器截图及实际查看 | 该视口和状态的可见布局 | 点击、键盘、完整业务链路可用 |
| DOM、溢出和资源检查 | 对应结构或资源异常 | 全面可访问性、视觉质量 |
| 自动截图差异 | 受控条件下的像素变化 | 改动是否符合用户设计意图 |
| 主路径操作与结果检查 | 实际走过的路径和状态 | 未覆盖路径、真实外部业务成功 |

没有实际测量方法和容差定义时，不报告“还原度 98%”等数字。

## 交互：执行操作并观察结果

从任务中选择主要路径，实际执行并验证结果，而不是只确认按钮存在：

- **导航或筛选：** 操作后内容、选择状态或目标路由正确；还要检查用户停留的阅读位置与后续焦点。用键盘切换列表后应能继续操作，阅读换篇后应能从新内容起点读；清除或返回后的状态符合需求。
- **表单：** 正常输入可继续；必填或格式错误有清楚反馈；恢复有效值后，过期校验应消除；失败后输入不丢失；成功状态与真实操作一致。
- **弹窗或菜单：** 打开、选择和关闭可用；键盘焦点合理进入，关闭后回到触发位置；适用时检查 Escape。
- **异步内容：** 需要时检查加载、空结果、失败及重试；不得为展示状态而影响真实用户数据。
- **错误与恢复：** 实际触发保存或加载失败，检查提示中的下一步能否执行、所指对象能否找到，以及重试和适用的返回、取消或放弃路径。不能只看到错误提示就算通过；用户离开时应知道哪些内容未保存，正在进行的不可逆操作仍按实际状态处理。
- **批量操作：** 改变勾选范围或目标后再次执行，核对实际处理对象、当前结果和提示。重试的成功数不能混入上一批；保留的历史状态应与本次结果分清。
- **可嵌入组件：** 在宽页面中的窄容器检查主要操作，不只缩小整个视口。按宿主用法检查移除再插入或多实例；涉及媒体、监听和观察器时，确认恢复后的实际行为，不能只检查外观仍在。

原型可使用本地或模拟流程，但报告必须说明这层边界。实际登录、付款、发送等业务成功，需相应真实结果支持，不能凭一个成功提示推断。

## 响应式和基本可访问性

- 在用户要求的屏幕测试；支持自适应时，至少查看主要视口与一个窄屏视口。断点按内容决定，不强行套固定设备清单。
- 检查文字可读、主操作可见、图片比例正常、必要内容可达。全页不应意外横向溢出；有意滚动的表格或画布应局限在自己的区域。
- 对按比例缩放的游戏或画布，实际查看最小目标尺寸中的操作文字和按键提示；检查缩放后的可读性与命中区域，不能用“没有溢出”代替。
- 用长标题、真实语言和足够条目检查内容增长；只检查本次范围内相关的情况。
- 键盘界面实际使用 Tab、Shift+Tab 和适用的 Enter、Space、Escape；触控界面检查点击、滚动、返回和软键盘；游戏按实际输入模式检查。焦点应可见、顺序合理、无非预期焦点陷阱。
- 检查控件的名称、表单标签和错误关联；状态不能只靠颜色表达。只声称实际检查过的可访问性范围。
- 浏览器或目标运行环境中的报错、关键资源加载失败和缺失图片需调查；将第三方噪声与阻断主流程的问题区分并说明。

## 验收记录

只保留与任务有关的简短记录：

```text
版本与环境：实际版本/工作副本标识，构建及运行位置。
参考与视口：所选图，原参考（如有），截图对应的尺寸与状态。
工程检查：实际执行的命令与结果。
视觉检查：截图路径、已查看的区域、发现并修正的主要偏差。
交互检查：执行的操作 → 观察到的结果。
已知限制：未验证项、残留差异及原因。
交付物：实际文件、预览入口或项目路径。
```

“未检查”“受阻”“检查失败”和“检查通过”应明确区分。不把清单全打勾当作覆盖证据。
